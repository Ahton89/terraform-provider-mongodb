# Resource: mongodb_user

Creates and manages MongoDB users with role-based access control. Users can have multiple roles across different databases. Passwords are stored in Terraform state.

Creates and manages MongoDB users with role-based access control (RBAC). Users can have multiple roles across different databases.

~> **Security Warning:** User passwords are stored in Terraform state files in plaintext. Use remote state with encryption and restrict access to state files.

~> **Note:** Changing the username requires resource replacement (destroy and recreate). The old user will be deleted.

## Example Usage

### Basic User Creation

```terraform
resource "mongodb_user" "app_user" {
  username = "application"
  password = var.app_user_password  # Store in variables, never hardcode

  roles = [
    {
      role     = "readWrite"
      database = "myapp"
    }
  ]
}
```

### User with Multiple Roles

```terraform
resource "mongodb_user" "admin_user" {
  username = "app_admin"
  password = var.admin_password

  roles = [
    {
      role     = "readWrite"
      database = "app_data"
    },
    {
      role     = "read"
      database = "analytics"
    },
    {
      role     = "dbAdmin"
      database = "app_data"
    }
  ]
}
```

### Read-Only User

```terraform
resource "mongodb_user" "readonly" {
  username = "reporting"
  password = var.reporting_password

  roles = [
    {
      role     = "read"
      database = "production"
    }
  ]
}
```

### Multiple Users with for_each

```terraform
locals {
  users = {
    developer = {
      password = var.dev_password
      roles = [
        { role = "readWrite", database = "development" }
      ]
    }
    analyst = {
      password = var.analyst_password
      roles = [
        { role = "read", database = "production" },
        { role = "read", database = "analytics" }
      ]
    }
  }
}

resource "mongodb_user" "users" {
  for_each = local.users

  username = each.key
  password = each.value.password
  roles    = each.value.roles
}
```

### With Custom Timeouts

```terraform
resource "mongodb_user" "service_account" {
  username = "service_account"
  password = random_password.service_account.result

  roles = [
    {
      role     = "readWrite"
      database = "services"
    }
  ]

  timeouts {
    create = "10m"
    read   = "5m"
    update = "10m"
    delete = "5m"
  }
}

resource "random_password" "service_account" {
  length  = 32
  special = true
}
```

### Complete Example with Database

```terraform
# Create database first
resource "mongodb_database" "app" {
  name = "myapp"
}

# Create user with access to the database
resource "mongodb_user" "app_user" {
  username = "app_service"
  password = var.app_password

  roles = [
    {
      role     = "readWrite"
      database = mongodb_database.app.name
    }
  ]

  depends_on = [mongodb_database.app]
}

# Output connection string (sensitive)
output "app_connection_string" {
  value     = "mongodb://${mongodb_user.app_user.username}:${mongodb_user.app_user.password}@${var.mongodb_host}:27017/${mongodb_database.app.name}"
  sensitive = true
}
```

## Import

Existing users can be imported using one of the following ID formats:

- `username` — uses default auth source `admin`
- `auth_source.username` — specify a non-default authentication database

```bash
# Default auth source (admin)
terraform import mongodb_user.example app_user

# Custom auth source (e.g., users_db)
terraform import mongodb_user.example users_db.app_user
```

**Example:**

```bash
# Import existing user named "app_user" from default auth DB (admin)
terraform import mongodb_user.app app_user

# Import existing user from a custom auth DB
terraform import mongodb_user.reporting users_db.reporting_user
```

After import:
- The password field must be set in your configuration
- Terraform cannot read the existing password from MongoDB
- Use a lifecycle rule to ignore password changes if needed:

```terraform
resource "mongodb_user" "imported" {
  username = "app_user"
  password = "temporary"  # Will be ignored

  roles = [
    {
      role     = "readWrite"
      database = "myapp"
    }
  ]

  lifecycle {
    ignore_changes = [password]
  }
}
```

~> **Warning:** System users (e.g., `admin`) cannot be imported.

## MongoDB Roles

Common built-in MongoDB roles:

### Database User Roles
- `read` - Read data from all non-system collections
- `readWrite` - Read and modify data on all non-system collections

### Database Administration Roles
- `dbAdmin` - Schema and indexing operations
- `userAdmin` - Create and modify users and roles
- `dbOwner` - Combines readWrite, dbAdmin, and userAdmin

### Cluster Administration Roles
- `clusterAdmin` - All cluster management operations
- `clusterManager` - Cluster monitoring and management
- `clusterMonitor` - Read-only access to monitoring tools
- `hostManager` - Monitor and manage servers

### All-Database Roles
- `readAnyDatabase` - Read all databases
- `readWriteAnyDatabase` - Read and write all databases
- `userAdminAnyDatabase` - Manage users on all databases
- `dbAdminAnyDatabase` - Admin operations on all databases

### Superuser Roles
- `root` - Full access to all resources

**Example with admin roles:**

```terraform
resource "mongodb_user" "superuser" {
  username = "terraform_admin"
  password = var.admin_password

  roles = [
    {
      role     = "root"
      database = "admin"
    }
  ]
}
```

## Security Best Practices

### Never Hardcode Passwords

❌ **Bad:**
```terraform
resource "mongodb_user" "bad" {
  username = "user"
  password = "hardcoded_password"  # Never do this!
  roles    = [...]
}
```

✅ **Good:**
```terraform
variable "user_password" {
  type      = string
  sensitive = true
}

resource "mongodb_user" "good" {
  username = "user"
  password = var.user_password
  roles    = [...]
}
```

### Use Random Password Generation

```terraform
resource "random_password" "db_user" {
  length  = 32
  special = true
}

resource "mongodb_user" "app" {
  username = "app_service"
  password = random_password.db_user.result
  roles    = [...]
}

# Store in AWS Secrets Manager
resource "aws_secretsmanager_secret" "db_password" {
  name = "mongodb/app_user/password"
}

resource "aws_secretsmanager_secret_version" "db_password" {
  secret_id     = aws_secretsmanager_secret.db_password.id
  secret_string = random_password.db_user.result
}
```

### Encrypt Remote State

```terraform
terraform {
  backend "s3" {
    bucket         = "terraform-state"
    key            = "mongodb/users.tfstate"
    encrypt        = true
    kms_key_id     = "arn:aws:kms:..."
    dynamodb_table = "terraform-locks"
  }
}
```

### Least Privilege Principle

Grant minimum required permissions:

```terraform
# ❌ Too permissive
resource "mongodb_user" "app" {
  username = "app"
  password = var.password

  roles = [
    { role = "root", database = "admin" }  # Overkill!
  ]
}

# ✅ Appropriate permissions
resource "mongodb_user" "app" {
  username = "app"
  password = var.password

  roles = [
    { role = "readWrite", database = "app_db" }  # Only what's needed
  ]
}
```

### Password Rotation

Implement password rotation:

```terraform
resource "time_rotating" "monthly" {
  rotation_days = 30
}

resource "random_password" "user" {
  length  = 32
  special = true

  keepers = {
    rotation = time_rotating.monthly.id
  }
}

resource "mongodb_user" "app" {
  username = "app"
  password = random_password.user.result
  roles    = [...]
}
```

## User Lifecycle

### Creation
1. Provider connects to MongoDB
2. Verifies user doesn't exist
3. Creates user with specified roles
4. Stores username and password in state

### Updates
Supported updates:
- Password changes
- Role modifications (add/remove/change)

Not supported (requires replacement):
- Username changes

**Update example:**
```terraform
# Add a new role
resource "mongodb_user" "app" {
  username = "app"
  password = var.password

  roles = [
    { role = "readWrite", database = "app_db" },
    { role = "read", database = "analytics" }  # New role
  ]
}
```

### Deletion
1. Provider connects to MongoDB
2. Drops the user
3. Removes from Terraform state

## Timeouts

User operations support configurable timeouts (default: 15 minutes):

- `create` - (Default: 15m) User creation timeout
- `read` - (Default: 15m) User read/refresh timeout
- `update` - (Default: 15m) User update timeout
- `delete` - (Default: 15m) User deletion timeout

**Example:**
```terraform
resource "mongodb_user" "example" {
  username = "user"
  password = var.password
  roles    = [...]

  timeouts {
    create = "5m"
    update = "5m"
    delete = "5m"
  }
}
```

## Troubleshooting

### Error: user already exists

```
Error: user myuser already exists
```

**Solution:** Import existing user:
```bash
terraform import mongodb_user.example myuser
```

### Error: not authorized

```
Error: not authorized on admin to execute command
```

**Solution:** Ensure Terraform MongoDB user has `userAdmin` role:

```javascript
// In MongoDB shell
db.getSiblingDB("admin").grantRolesToUser("terraform_user", [
  { role: "userAdminAnyDatabase", db: "admin" }
]);
```

### Error: invalid role

```
Error: role invalidRole does not exist
```

**Solution:** Use valid MongoDB role or create custom role first. See [MongoDB Roles](#mongodb-roles) for valid built-in roles.

### Error: cannot delete default user

```
Error: user admin is a default user and cannot be deleted
```

**Solution:** System users cannot be managed. Remove resource from Terraform configuration.

### Password Not Updating

If password changes aren't being applied:

1. Check for `ignore_changes` lifecycle rule
2. Verify plan shows password change (will show as `(sensitive value)`)
3. Check MongoDB logs for authentication errors

```terraform
# Force password update
terraform taint mongodb_user.example
terraform apply
```
